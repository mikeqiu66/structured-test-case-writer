# 覆盖矩阵模板

适用于存在多维条件组合的项目，用于在写正式测试用例前先确认覆盖范围，避免漏测。

## 推荐矩阵维度

按项目实际情况选择，不要求每次都全用，但复杂项目至少要检查以下维度：

- 版本维度：旧版 / 新版 / 升级后
- 状态维度：主页 / 配置页 / 日程页 / 异常页 / 模式页
- 模式维度：正常模式 / 船运模式 / 添加模式 / 恢复出厂流程
- 数据维度：空数据 / 正常数据 / 边界数据 / 脏数据
- 网络维度：正常 / 弱网 / 断网 / 恢复后
- 时间维度：普通时段 / 特定窗口 / 跨天 / 跨月 / 跨年
- 用户维度：本人 / 多成员 / 切换中
- 行为维度：单击 / 长按 / 连续操作 / 并发触发

## 输出方式二：组合矩阵

| 核心场景 | 版本 | 状态/模式 | 网络 | 时间 | 数据 | 是否需要用例 |
|---|---|---|---|---|---|---|
| 主流程 | 新版 | 正常态 | 正常 | 普通时段 | 正常数据 | 是 |
| 异常恢复 | 新版 | 异常页 | 断网→恢复 | 普通时段 | 正常数据 | 是 |
| 兼容验证 | 旧版/新版 | 正常态 | 正常 | 普通时段 | 正常数据 | 是 |
| 时间窗口 | 新版 | 定时逻辑中 | 正常 | 特定窗口/跨天 | 正常数据 | 是 |

## 使用原则
1. 先补矩阵，再写用例。
2. 如果矩阵中某个高风险组合未覆盖，要明确说明原因。
3. 同一维度不需要机械穷举，但必须覆盖高风险组合。
4. 有版本兼容、状态切换、时间窗口、并发逻辑的项目，默认需要矩阵。
