# 问题澄清项模板

适用于需求口径未完全收敛的项目。在正式测试用例前，先输出问题澄清项，避免后续大量返工。

## 推荐字段

| 编号 | 模块 | 问题描述 | 当前理解 | 风险 | 需要谁确认 | 状态 |
|---|---|---|---|---|---|---|
| Q-001 |  |  |  |  |  | 待确认 |
| Q-002 |  |  |  |  |  | 待确认 |

## 优先关注的问题类型

### 1. 默认态
- 页面默认进入哪一页
- 默认成员是谁
- 默认分页/默认模式是什么

### 2. 回退逻辑
- 失败后回到哪里
- 中断后恢复到什么状态
- 高优先级事件结束后恢复到哪一页

### 3. 状态保留逻辑
- 离开页面后是否记住上次状态
- 重启后是否保留状态
- 切换成员/模式后是否重置

### 4. 版本兼容口径
- 旧版是否沿用旧逻辑
- 新版是否强制切换新逻辑
- 升级过程中是否存在兼容窗口

### 5. 并发/冲突逻辑
- 两个动作同时发生时谁优先
- 用户操作与后台调度冲突时如何处理
- 下载/刷新/切页/提醒同时发生时谁生效

### 6. 时间窗口逻辑
- 哪些逻辑只在特定时段生效
- 跨天/跨月/跨年时口径如何定义

## 输出要求
1. 问题描述要具体，不要写成泛泛而谈。
2. 当前理解必须写清楚，否则后续无法判断是否已闭环。
3. 风险要指出不确认会影响什么：漏测、误判、返工、无法执行等。
4. 后续应继续维护状态：`待确认 / 已确认 / 暂不处理 / 已变更`。

## 建议用法
- 在“需求拆解”和“测试点梳理”之后输出。
- 在“正式测试用例”之前先过一遍。
- 高风险未确认项要在正式用例备注中显式标记。
